# Редактор интерфейса Manashelper

Vue 3, TypeScript и Vue Flow. Управление зависимостями, генерация типов, сборка,
форматирование и тесты выполняются через Bun. Node.js и npm для запуска frontend
не используются. Зафиксирован `bun.lock`; проверено на Bun 1.4.3.
Интерфейс админки и fallback-страница входа — только EN. Языкового переключателя
админки нет. Тексты бота, кнопки, формы и preview поддерживают EN/RU/KY/TR/ZH.
В заголовке Release переключает Admin only / All users / Off. Изменение требует
подтверждения и актуальной ревизии. Off запрещает новые запуски, но сохраняет
обработку начатых диалогов. [Запуск, Docker и откат](../../features/ui_flows/RELEASE.md).

## Сборка и запуск

Из каталога `src/admin-ui/`:

```sh
bun install --frozen-lockfile
bun run build
```

Из корня проекта настроить development-базу и параметры административного доступа
по [ADMIN_API.md](../../features/ui_flows/ADMIN_API.md), применить миграции и запустить:

```sh
env MANASHELPER_TELEGRAM_TRANSPORT=polling uv run python -m manashelper.main
```

Общий aiohttp host автоматически отдаёт `src/admin-ui/dist/index.html` и только каталог собранных
`assets` по `/admin/`. Исходники, конфигурация и checkout через этот маршрут не доступны.
Для входа нужен HTTPS-прокси к `127.0.0.1:8080`, совпадающий с
`MANASHELPER_ADMIN_WEB_ORIGIN`. В приватном чате администратора отправить `/editor`
и открыть кнопку Mini App либо совместимую браузерную ссылку. Без сборки остаётся
минимальная ticket/cookie-страница входа, без графического редактора и Mini App shell.
Отдельного `admin_main`/FastAPI/Uvicorn процесса нет: main также обслуживает Telegram
и scheduler. Polling для development выбран явно; production по умолчанию использует
webhook. Регистрация/удаление webhook выполняется оператором отдельно, с сохранением
pending updates. Один bot token не должен одновременно работать с двумя transport.

Для разработки `bun run dev` поднимает Vite на loopback. API проксируется на
`127.0.0.1:8080`; браузерный адрес также должен быть за HTTPS-прокси, например на
localhost. Настроенный Origin должен совпадать с этим адресом. Secure-cookie и
проверки Origin/CSRF для разработки не отключаются.

## Telegram Mini App и авторизация

`/editor` доступен только настроенному приватному администратору. Основная кнопка
`web_app` открывает HTTPS `/admin/`. Клиент передаёт исходные Telegram `initData`
в POST `/admin/api/v1/auth/telegram`; сервер проверяет подпись, возраст не более
пяти минут и admin user ID. Ответ содержит `user_id`, `expires_at`, `access_token`.
Bearer-сессия действует восемь часов, token хранится только в памяти `AdminApi` и
передаётся через `Authorization`. `initDataUnsafe` не считается аутентификацией.
На host разрешены пять корректных обменов за минуту; следующий получает 429.

Обычная браузерная ссылка сохраняет совместимый вход: одноразовый ticket действует
пять минут, передаётся во fragment и удаляется до POST `/auth/exchange`. Браузерная
сессия использует восьмичасовую Secure/HttpOnly/SameSite=Strict cookie. В обоих
режимах изменяющие запросы требуют точного Origin; только cookie-режим дополнительно
использует `X-CSRF-Token`. Ticket, initData, bearer и CSRF не сохраняются в
localStorage/sessionStorage, query URL, экспортируемом графе или логах. Cookie
и bearer не взаимозаменяемы; logout отзывает текущую сессию.

Официальный SDK вызывает `ready()`, запрашивает fullscreen на API 8.0+ и учитывает
`fullscreenChanged`/`fullscreenFailed`. `expand()` служит fallback, а не признаком
успешного fullscreen. Layout учитывает stable viewport, safe area и content safe
area. На узком экране палитра и свойства открываются по отдельности, оставляя граф
основной областью. Telegram BackButton закрывает текущую панель/диалог, а выход
при несохранённом черновике требует подтверждения. SDK closing confirmation также
включается при несохранённых изменениях.

## Работа со сценарием

Раздел **Texts** управляет пользовательским DB-каталогом: поиск ключа/текста,
редактирование языка, темы и plural form, безопасный preview, Save, отдельный Publish
и Activate старого выпуска. 409 сохраняет правки; Reload требует подтверждения
их удаления. Переход между режимами сохраняет несохранённый перевод, а closing guard
учитывает его вместе с графом. Контракт ключа/параметров read-only. После публикации
переводов нужно снова сохранить черновик сценария (можно без изменения графа), затем
Publish: новая ревизия закрепит новый каталог. Затем сохранить и опубликовать новую
ревизию **Triggers**, чтобы обычные входы приняли новый сценарий/каталог.
Повтор Publish прежней ревизии
идемпотентен. Users читает каталог закреплённой версии.

Раздел **Triggers** добавляет private command/deep-link/prefix/reply entries, target/entry,
доступ, launch policy и явные argument bindings. Compatibility entries read-only.
Save создаёт новую ревизию даже без изменения bindings для обновления pins.
Publish и Activate требуют подтверждения; 409 сохраняет правки, Reload требует discard.
Переключение режимов, signout и SDK closing guard учитывают trigger draft.
Published manifest фиксирует сценарии, тексты и return targets. Откат сохраняет draft
и активные сессии. [Контракт/API](../../features/ui_flows/TRIGGERS.md).

1. Создать сценарий со стабильным ID. Начальный документ содержит меню и завершение.
2. Добавить узлы из палитры. На правой панели настроить тексты, ряды кнопок, переходы,
   ввод, условия и разрешённые Python-делегаты. Соединитель каждого выхода меняет
   соответствующий переход схемы; перемещение узла меняет только `layout`.
3. В разделе «Поля данных» объявить поля и начальные значения. Ссылки параметров
   используют `data`, `user` или разрешённые `capabilities`.
4. Для собственного текста заполнить английский fallback и нужные варианты
   `ru`, `ky`, `tr`, `zh`, включая Halloween. Готовый перевод выбирается из серверного
   каталога; преобразование в собственный текст сохраняет его локали и тему.
5. Проверить документ. Ошибки показывают код и путь поля; нажатие выделяет узел.
   Несохранённые изменения отмечены; переход к другому сценарию и перезагрузка
   черновика требуют явного отказа от них.
6. В предпросмотре выбрать локаль, тему и тестовые значения. Для используемых действий
   явно включить заглушки и задать их исходы/результаты. Исполнение идёт через серверный
   интерпретатор, без реальных делегатов, Telegram-сообщений и записей ответов.
7. Сохранить черновик, затем отдельно подтвердить публикацию. Откат через «Версии»
   переключает опубликованную версию для новых сессий и не заменяет черновик.
8. Для административного Telegram-пилота завершить или отменить текущий диалог и
   отправить `/flow_demo <id>`. Команда без аргумента сохраняет прежний демо-сценарий.
   Другие пользователи и группы не могут запускать этот пилот.

При 409 редактор сохраняет локальные правки; оператор решает, загружать ли серверную
ревизию. Автоматического повтора записи нет. JSON можно экспортировать и импортировать
в текущий сценарий с тем же ID. Импорт проходит серверную проверку структуры и не
публикуется автоматически. Данные формы и авторизация не пишутся в browser storage.

После запуска бота в списке появляется `main_menu`: главное меню и «Учёба» импортируются
однократно. Для администратора `/start` и глобальный возврат открывают опубликованную
версию; допуск остальных пользователей определяется режимом Release. В «Полях данных»
настраивается вход в «Учёбу». Переименование узла сохраняет эту связь.

Узел завершения поддерживает открытие одной из девяти существующих функций через
`feature`; Eders/Study week доступны только при включённом флаге. Передача управления
не вызывает handler напрямую. `Return to flow` у завершения задаёт ID опубликованного
сценария с начальным Menu/Input. В Telegram возврат и сохранение ответа атомарны;
preview показывает намерение возврата без запуска реального диалога.

После запуска бота также появляется `student_questions`: граф студенческого опроса.
Для администратора он доступен через `/start student_questions`. Прежняя завершённая
анкета заменяется только после подтверждения и полного нового прохода. Начатые legacy-
опросы продолжают старый маршрут. [Описание и проверки](../../features/ui_flows/SURVEY.md).

Вкладка «Пользователи» показывает зарегистрированные ID, текущий runtime-шаг или
последний наблюдавшийся legacy-шаг, владельца, время, результат runtime-доставки и
историю. Поиск работает по Telegram ID. Список/история имеют пагинацию. Обновление
выполняется каждые пять секунд, пока страница видна; кнопка «Обновить» выполняет его сразу.
Граф читается из закреплённой версии, доступен только для просмотра и выделяет текущий
узел. Новая публикация не подменяет граф активной формы. Правки редактора сохраняются
в памяти при переключении вкладок. Данные ответов и содержимое FSM не показываются.
После перезапуска legacy-положение отмечается неизвестным, с сохранением времени и
названия последнего наблюдения. [Подробности](../../features/ui_flows/MONITORING.md).

## Контракты, переводы и проверки

`src/generated/api.d.ts` выводится из существующего OpenAPI. Системный текст редактора
остаётся в английском `.po`-каталоге; `editor_copy.py` содержит извлекаемые gettext-вызовы.
Сгенерированный `messages.json` используется браузером. После изменения контрактов
или каталогов из корня проекта:

```sh
uv run python scripts/export_ui_flow_contracts.py
uv run pybabel compile -d src/manashelper/locales
uv run python scripts/export_ui_flow_editor_copy.py
```

Из `src/admin-ui/`:

```sh
bun run generate
bun run build
bun run test
bun run format:check
bun run test:e2e
```

Проверка локализационного bundle: `uv run python scripts/export_ui_flow_editor_copy.py --check`.
Сборка проверяет актуальность API-типов и выполняет `vue-tsc`. E2E-команда сначала
собирает свежий frontend, затем запускает Playwright через Bun и настоящий aiohttp host
с development PostgreSQL в отдельной случайной схеме. Для первого запуска установить
браузер через `bun --bun playwright install chromium`. Python использует существующую
`.venv`; development `.env` нужен для подключения к локальному Postgres.

Тестовый сервер слушает только `127.0.0.1:8091`, создаёт временный TLS-сертификат и
синтетического администратора. Его `__test__`-маршруты существуют только в тестовом
модуле, не в production-приложении. `/__test__/init-data` выдаёт подписанные synthetic
launch data для SDK mock. Global teardown вызывает `/__test__/cleanup`: сервер
сначала прекращает HTTP-приём и завершает запросы, затем удаляет созданную схему.
Для проверки рядом с работающим демо задать `UI_EDITOR_TEST_PORT=8092`;
порт должен быть свободен, отдельная временная схема создаётся автоматически.
Проверяются все пять видов узлов, соединение мышью, сохранение,
публикация, проход формы, заглушки, конфликт ревизий, выделение ошибки и откат.
Mini App E2E использует SDK mock и локальный HTTPS; это не доказывает настоящий
fullscreen или запуск webhook. Перед выпуском отдельно проверить production
HTTPS-прокси и живой тестовый Telegram на нужных Android/iOS/Desktop/Web-клиентах.
Итоговые результаты проверок переноса host/auth фиксируются отдельно.
