# Опрос через визуальный граф: этап 7

Студенческий опрос перенесён в runtime для приватного администратора. Остальные
пользователи продолжают существующий опрос до этапа выпуска. Пользовательские
тексты, кнопки, темы и preview сохраняют пять языков. Админка и запасная страница
веб-входа работают только на английском; язык браузера их не переключает.

## Запуск и владение

`modules/student_questions/flow.py::survey_document` задаёт начальный документ
`student_questions`. Он совпадает с проверенным fixture по поведению и использует
существующие catalog keys, enum курсов и `ANSWER_MAX_LENGTH`. Layout принадлежит
редактору. Бот создаёт и публикует документ только при отсутствии, после публикации
`main_menu`. Существующие черновики, версии и указатели не перезаписываются.
Если оператор уже создал неопубликованный корень, опрос ожидает его публикации.

`/start student_questions` для администратора обрабатывается до общего deep-link
маршрута рекламы. Новый запуск отменяет активный runtime в той же транзакции.
Если MemoryStorage содержит `StudentQuestionsForm:*`, владелец остаётся legacy:
такая форма проходит прежние handlers до окончания или отмены. Другие пользователи
сохраняют прежний маршрут. Глобальная навигация сохраняет текущую семантику выхода.

Устаревшие legacy callbacks проверяют session ID и state. Их отклонение не отменяет
новый runtime-опрос. Runtime callbacks дополнительно связаны с чатом, пользователем,
сообщением, токеном и ревизией; старые финальные кнопки не записывают ответ повторно.

## Ветки и сохранение

Граф выполняет `student_questions.has_submitted`, затем открывает выбор курса либо
явное подтверждение замены. Курс включает подготовительное отделение, годы 1–5
и вариант «не студент». Ветка без вопросов пропускает свободный ввод. Ветка с
вопросами запрашивает текст и наличие найденного ответа; источники нужны только
при положительном ответе. Последний вопрос определяет согласие на beta-тестирование.

Пустой/пробельный текст и ввод длиннее 4000 символов сохраняют текущий шаг.
Нормализация и окончательная бизнес-проверка остаются в StudentQuestionsService.
Предыдущая завершённая анкета сохраняется до последнего шага нового прохода;
отмена подтверждённой замены не удаляет и не изменяет её. При гонке первой записи
делегат возвращает `already_submitted`, переводя граф к подтверждению замены.

`student_questions.submit` использует прежний публичный сервис и REQUEST-транзакцию.
HTTP-вызовов под блокировкой чата нет. Preview создаёт отдельный реестр с явными
заглушками и не записывает ответы, сессии либо переходы пользователей.

## Возврат в меню и повтор событий

Telegram включает `DialogService` с `follow_returns=True`. После End с `return_flow`
исполнитель сохраняет завершённую исходную сессию и создаёт новую на текущей
опубликованной версии целевого сценария. Начальный узел цели обязан быть Menu/Input;
проверка публикации и runtime отклоняют автоматический вход, ограничивая циклы.
Исходные ответы не копируются в новую сессию.

Миграция `41edcfaadf86` добавляет nullable `ui_flow_events.result_session_id` с FK
`SET NULL`. Старые строки и старые writers не требуют изменений. Событие сохраняет
исходную сессию/терминальный шаг и ссылку на результирующую сессию. Повтор возвращает
ту же результирующую сессию без нового делегата или создания ещё одного меню.

Ответ, исходное завершение, новое меню, событие, общая проекция и screen intent
фиксируются вместе. Ошибка цели или renderer откатывает всю операцию, включая
бизнес-запись, даже если вызывающий код поймал ошибку внутри внешнего scope.
Проверенный итоговый экран объединяет сообщение благодарности/отмены с текстом
и клавиатурой целевого меню. Сеть начинается только после commit и claim intent.

Downgrade удаляет только новый FK/столбец, сохраняя пользователей, ответы, события,
версии и сессии. Это проверка обратимости схемы, а не механизм production-отката:
переключение запуска и обработка уже активных сессий остаются этапом 8.

## Работа в редакторе

Открыть `student_questions`, затем Properties для редактирования или Preview для
тестового прохода. В Preview включить явные результаты двух survey-делегатов.
Для `has_submitted` выбрать `submitted=false` для нового ответа или `true` для
подтверждения замены. Для submit доступны `success` и `already_submitted`.
Выбор Language меняет только содержимое бота; интерфейс редактора остаётся EN.
Завершение показывает `Return to flow: main_menu`, без реального запуска меню.

## Проверки

Проверены все ветки с/без beta, соответствие семи курсов существующему enum,
нормализация текста, отмена замены, отсутствие ранней записи, продолжение legacy,
устаревшие callbacks, закреплённая версия после рестарта, сохранение правок при
повторном bootstrap, конкурентные финальные события и rollback неверного возврата.
Миграция проверена upgrade/downgrade/upgrade в отдельной схеме PostgreSQL.

Полная регрессия: 903 passed, 29 skipped. Ruff, format, strict mypy, экспорт схем,
независимый OpenAPI validator и `alembic check` прошли. Frontend использует Bun:
9 unit и 6 браузерных E2E прошли, включая пять языков опроса при EN-интерфейсе.
Дополнительно 7 HTTP-тестов прошли через настоящий aiohttp/aiogram и локальную
Postman-симуляцию Telegram, включая финальную запись/возврат и повтор callback.
Проверка живым тестовым ботом, HTTPS-прокси и общее включение остаются этапом 8.
