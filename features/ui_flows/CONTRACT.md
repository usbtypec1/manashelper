# Контракт визуального интерфейса: версии 1 и 2

Реализованы Python-контракты, исполнитель, PostgreSQL-хранилище, Telegram-адаптер,
административный HTTP API и Vue-редактор с мониторингом пользователей. Нумерация
этапов 1–8 в исходном [UI_FLOW_EDITOR_PLAN.md](../UI_FLOW_EDITOR_PLAN.md) относится
к редактору. Новый [ORCHESTRATION.md](ORCHESTRATION.md) задаёт отдельные этапы:
5 — композиция v2, 6 — структурированные данные, динамические экраны и внешние эффекты.
Эти механизмы реализованы; перенос всех feature UI и удаление FSM относятся к этапам 7–12.
Меню и опрос входят через опубликованные bindings и режим Release admin/all/off;
начатые legacy-сессии сохраняют владельца. [Опрос](SURVEY.md), [запуск и откат](RELEASE.md).
См. [RUNTIME.md](RUNTIME.md), [TELEGRAM.md](TELEGRAM.md) и [MONITORING.md](MONITORING.md).
Исходный план редактора: [UI_FLOW_EDITOR_PLAN.md](../UI_FLOW_EDITOR_PLAN.md).

## Источники истины

- [schema.py](../../src/ui_flows/domain/schema.py) определяет формат сценария.
- [contracts.py](../../src/ui_flows/domain/contracts.py) определяет события, статусы и Python-делегат.
- [validation.py](../../src/ui_flows/application/validation.py) проверяет связи с явно переданным каталогом возможностей.
- `src/manashelper/modules/ui_flows/presentation/{admin_contracts,openapi}.py` определяют административный API.
- [flow.schema.json](flow.schema.json) и [openapi.json](openapi.json) генерируются из этих Python-контрактов.
- Контрольные сценарии и описания делегатов находятся в `tests/fixtures/ui_flows/`.
  Исходные production-документы меню и опроса находятся в owning-модулях;
  fixtures проверяют их контракт, а опубликованные версии хранятся в БД.

Экспорт и проверка актуальности:

```sh
.venv/bin/python scripts/export_ui_flow_contracts.py
.venv/bin/python scripts/export_ui_flow_contracts.py --check
.venv/bin/pytest tests/modules/ui_flows -q
```

Произвольные поля запрещены. Идентификаторы узлов и кнопок стабильны, не зависят
от подписей и локали. `schema_version` версионирует формат; номер опубликованного
сценария хранится отдельно. Изменение формата требует нового контракта и политики миграции.

Необязательное `navigation_entries` задаёт именованные входы глобальной навигации.
Сейчас поддерживается `study`: значение должно ссылаться на существующий узел Menu.
При отсутствии поля используется пустой словарь; редактор обновляет ссылку при
переименовании узла.

## Узлы и данные

`menu` показывает текст и строки inline/reply-кнопок. `input` ожидает значение,
проверяет ограничения и записывает его в объявленное поле. `condition` выбирает
первую подходящую ветку, иначе использует обязательный `default`. `action` выполняет
зарегистрированный делегат конкретной версии. `end` завершает, отменяет или передаёт
владение ввода legacy-функции в совместимом формате v1. V2 добавляет `call`, `return`
и `replace`: типизированный вызов дочернего сценария, возврат только объявленных
результатов и замену исполнения новой сессией. Поля и ограничения определены в
[сгенерированной схеме](flow.schema.json) и `src/ui_flows/domain/schema.py`.

Ссылки имеют вид `{"kind":"ref","scope":"data","field":"course"}`.
Значения могут быть литералами. V2 поддерживает scalar/list/object и непрозрачные
UUID secret handles. Коллекции объявляют тип элемента и максимальный размер,
объекты — свойства; глубина данных ограничена восемью уровнями. Ссылка может
содержать `path` длиной до восьми ключей/индексов. Доступны четыре пространства имён:

- `data`: объявленные поля конкретной формы;
- `user`: `id`, `chat_id`, `locale`, `theme`, полученные от доверенного адаптера;
- `capabilities`: явно зарегистрированные настройки, для контрольного меню — `eders_enabled`.
- `item`: текущий объект при разворачивании шаблона динамических кнопок.

Контекст пользователя нельзя задавать пользовательской кнопкой: `assignments`
изменяет только объявленные поля `data`. Ввод не выполняет автоматическое
преобразование между bool, строкой и числом. Runtime явно разбирает integer,
после чего проверяет результат контрактом.

`eq`/`ne` сравнивают значения; `in` принимает список литералов. Числовые операторы
работают только с числами. `exists` означает наличие непустого в смысле None значения:
False, 0 и пустая строка сами по себе существуют. Группы `all`/`any` содержат атомарные
условия, без рекурсивно вложенных групп. Отсутствующее nullable-поле читается как None;
отсутствующее обязательное значение для Action является ошибкой исполнения, а не
поводом вызывать делегат с частичными аргументами. Сравнения порядка с None дают False.

URL-кнопка не меняет шаг. `transition` может записать фиксированный ответ и открыть
целевой узел. Возврат внутри формы — обычный явный переход; отмена — переход в
`end(status=cancelled)`. Меню может содержать ручные циклы. Цикл из одних Action и
Condition отклоняется; runtime ограничивает общую цепочку 32 автоматическими шагами,
включая вызовы и возвраты. Максимальная глубина композиции — 16 сценариев.

Вызов сохраняет durable frame родителя и начинает дочерний сценарий с отдельными
локальными данными: его initial_data и явно переданными inputs. Return восстанавливает
родителя и копирует только объявленные outputs. Публикация закрепляет неизменяемые
версии дочерних сценариев; последующая публикация ребёнка не меняет родителя или
активную сессию. Рекурсивные зависимости запрещены. Replace закрывает прежнюю сессию,
создаёт новый ID и сохраняет связь результата для replay без повторного перехода.

`menu.repeated` разворачивает типизированные объекты в кнопки. Сохранённый экран
содержит snapshot действия: template ID, target, присваивания и выбранный объект.
Callback/reply использует этот snapshot; новый порядок исходной коллекции не меняет
смысл уже показанной кнопки. Inline-кнопки передают короткий delivery token и индекс.

Menu/Input могут добавить локализованные сообщения, plain-text `message_source` и
ссылку на коллекцию фото/видео. Всего допустимо двадцать дополнительных сообщений и
десять медиа. Plain text экранируется один раз; caption ограничен 1024 UTF-16 units
после разбора HTML. Экран хранит все подтверждённые message IDs, включая частичную
доставку. Обновление существующих экранов и feature-specific ephemeral delivery
остаются задачами миграции соответствующих функций. См. [TELEGRAM.md](TELEGRAM.md).

`layout` хранит только координаты узлов. Изменение координат не меняет исполнение.
Публикация дополняет статические проверки границами композиции, доступностью
делегатов/адаптеров, Telegram HTML/длинами и неоднозначностью reply-подписей.
Динамические значения дополнительно проверяются при исполнении.

## Тексты и темы

`catalog` ссылается на стабильный ключ versioned DB-каталога. В
`modules/ui_flows/catalog.py` сохраняются буквальные вызовы `_()`, доступные Babel.
Разрешение происходит внутри явно привязанного snapshot, локали и темы получателя.
Публикация сценария закрепляет text release; активные сессии и delivery intents
сохраняют этот pin. Пользовательского runtime fallback на `.mo` нет. `.po` остаются
baseline/recovery материалом. См. [LOCALIZATION.md](LOCALIZATION.md).

`inline` представляет редактируемое содержимое сценария: варианты en/ru/ky/tr/zh,
обязательный en и необязательные Halloween-варианты. Порядок fallback описан в плане.
InlineText хранится внутри неизменяемой опубликованной версии сценария.
Административный интерфейс English-only; его системные сообщения извлекаются из
английского каталога и экспортируются в браузерный bundle.

Оба типа явно связывают именованные параметры с литералом или ссылкой на контекст.
`inline` проверяет совпадение имён параметров во всех локалях и темах. Доступ к
атрибутам, индексам, conversion и format spec внутри строкового placeholder запрещён;
структурированный доступ задаётся отдельным `ReferenceValue.path`. Renderer экранирует
динамические значения, проверяет Telegram HTML/длины; browser preview создаёт Vue VNodes.

## Контракт делегата

Определение содержит ID, версию, тип эффекта (`read`, `database_write` или `external`), входы,
выходы и допустимые исходы. Action связывает аргументы с контекстом, выходы — с
полями формы, а каждый исход — с переходом. Python-импорт или скрипт из схемы не выполняется.

`Delegate` — async callable, принимающий `DelegateContext` и аргументы, возвращающий
`DelegateResult(outcome, values)`. Контекст несёт user/chat/session/event ID; HTTP
и Telegram-объектов в контракте нет. Сервисы и транзакционная сессия предоставляются
реализации через Dishka. Реестр проверяет входы, исходы и типы результатов до
применения; числа NaN/Infinity запрещены. Неожиданное исключение не становится
автоматически веткой success. `read` и `database_write` исполняются в той же
DB-транзакции. `external` требует v2, waiting_text и отдельной durable операции:
pending → unknown до I/O → succeeded → applied. Внешний callable вызывается после
commit REQUEST, без DB chat lock. Неизвестные и failed операции автоматически не
повторяются; сохранённый succeeded result применяется отдельно после проверки
исходных session/flow/version/node/revision. Подробнее — [RUNTIME.md](RUNTIME.md).

Для опроса предусмотрены `student_questions.has_submitted` и `student_questions.submit`.
Первый читает наличие ответа; второй вызывает существующий StudentQuestionsService.
Исход `already_submitted` возвращает на экран подтверждения замены. Отмена и шаги
ввода не вызывают submit. DB-запись и финальное состояние сессии должны фиксироваться
одной транзакцией. Реестр также содержит `users.set_locale` и `users.set_theme`;
соответствующие сценарии подготовлены, но глобальные locale/theme triggers ещё
принадлежат legacy UI. Production external registry пока не содержит feature-адаптеров.
Preview использует отдельный реестр и только явные stubs, включая чтения и external.

## События, владение и наблюдение

События button/input/contact/media/secret/navigation несут `update_id`, user/chat/session ID и
`expected_revision`. Это контракт нормализованного события, а не Telegram callback_data:
callback использует короткий токен и серверное сопоставление с ограничением 64 байта.
Входящий user_id, сессия, ревизия и разрешённость кнопки проверяются сервером.

Contact проверяет владельца контакта. Media сохраняет типизированные элементы и
дедуплицирует message_id при накоплении альбома. Secret input сохраняет только UUID
handle; plaintext шифруется AES-GCM отдельно с привязкой к session/user/chat и TTL
пять минут. Plaintext не входит в state, event receipt, screen, history или preview.

Состояние различает running, ожидание кнопки/ввода/внешнего эффекта, completed, cancelled, handed_off,
failed. Доставка отдельно имеет pending/sent/failed/unknown. Статус sent не доказывает
прочтение. Проекция положения и API истории не содержат текст ввода и ответы формы.
Сам InputEvent нужен для обработки, но его repr скрывает текст. Обработчики ошибок
не должны записывать целиком event, Pydantic validation input или тело запроса.

Один приватный чат принадлежит либо runtime, либо legacy-функции. Глобальные start,
Back и deep links выбираются до обработчика ввода формы; порядок deep links из
dispatcher сохраняется. Локальное «назад» отличается от глобальной отмены. Для старых
форм наблюдаются только имена состояний; MemoryStorage не становится долговечным
из-за добавления мониторинга.

## Административный API

Реализованный интерфейс описан в [openapi.json](openapi.json). Генератор не импортирует
FastAPI и не запускает приложение. Модели запроса/ответа — источник TypeScript-типов.

Черновик сохраняется с expected_revision. Публикация одной ревизии повторно возвращает
тот же номер версии, не создавая дубль и не отменяя последующий rollback. Активация
версии отдельно использует expected_published_version. Активные формы остаются на
старой версии. Билет входа одноразовый, 5 минут; сессия администратора — 8 часов.
Browser mutations проверяют настроенный HTTPS Origin. Cookie-аутентификация также
требует CSRF; Mini App bearer хранится только в памяти браузера. Preview изолирован
от реальных данных и бизнес-действий. См. [ADMIN_API.md](ADMIN_API.md).

Документы проходят Python-проверки и независимую валидацию OpenAPI. Это проверка
контракта; runtime, PostgreSQL, HTTP и browser-поведение проверяются отдельно.
